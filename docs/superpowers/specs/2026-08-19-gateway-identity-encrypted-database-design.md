# 网关身份加密数据库存储设计

## 背景

DBX 当前将网关客户端证书链和 PKCS#8 私钥序列化、Base64 编码后，作为一个密码条目写入操作系统凭据库。Windows Credential Manager 的通用凭据数据大小有限，常见的客户端证书链加私钥会超过限制。当前实现还把所有 `keyring` 错误统一映射为“操作系统凭据存储不可用或已锁定”，因此大小超限也会显示为凭据库故障。

本次修改将完整网关身份保存为 `dbx.db` 中的加密密文。操作系统凭据库只保存一个固定长度的 32 字节主密钥。

## 目标

- 导入正常的 `.p12` 和 `.pfx` 网关客户端身份时不受 Windows Credential Manager 条目大小限制。
- 证书私钥不得以明文形式写入数据库、日志或错误信息。
- modern Windows、Windows 7/8、macOS 和 Linux 使用相同的数据库密文格式。
- 多个 DBX 实例共享同一个数据目录时，可安全读取身份并串行完成首次主密钥初始化。
- 已经成功保存在旧版系统凭据库中的身份能够按需迁移。
- 错误信息应反映实际失败阶段，不再把所有错误归类为凭据库锁定。

## 非目标

- 本次不提供跨主机导出、备份或同步网关私钥的功能。
- 本次不使用用户口令派生主密钥，也不增加启动解锁界面。
- 本次不改变 PKCS#12 解析、证书校验、网关协议或身份元数据的用户界面。
- 本次不迁移普通数据库连接密码的现有存储方式。

## 存储模型

在 SQLite 中新增网关身份密文表，概念结构如下：

```sql
CREATE TABLE gateway_identity_secrets (
  identity_id TEXT PRIMARY KEY NOT NULL,
  format_version INTEGER NOT NULL,
  nonce BLOB NOT NULL,
  ciphertext BLOB NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

另存一个不敏感的主密钥状态记录，包含密钥格式版本和主密钥 SHA-256 指纹。该记录用于检测系统凭据库中的密钥是否与当前数据库匹配，不包含主密钥本身。

加密明文沿用现有 `StoredIdentity` 语义，包含完整 DER 证书链和 PKCS#8 私钥。数据库只保存 AES-256-GCM 密文。每次写入生成独立的 96 位随机 nonce，AAD 固定绑定以下字段：

```text
DBX-GATEWAY-IDENTITY\0<format-version>\0<identity-id>
```

绑定身份 ID 可防止攻击者在数据库内交换两条身份密文而不被发现。

## 主密钥管理

系统凭据库保存一个 32 字节随机主密钥：

- service：`fun.dbx.gateway`
- account：`master-key-v1`
- 值：32 字节随机数据，使用 `keyring` 的二进制 secret API

首次需要保存网关身份时才初始化主密钥。初始化和首次密文写入必须受 SQLite 写事务串行化：

1. 开启能够阻止其他写入者进入同一初始化流程的事务。
2. 读取数据库中的主密钥状态。
3. 若状态不存在，先尝试读取系统凭据库中的主密钥。
4. 凭据条目也不存在时，生成 32 字节随机主密钥并写入凭据库。
5. 重新读取凭据条目，确认实际持久化的密钥，并将其指纹写入数据库。
6. 使用该密钥加密身份，在同一事务内写入身份元数据和密文。
7. 提交事务。

若进程在写入系统凭据后、提交数据库前退出，下次初始化会复用已经存在的主密钥。若数据库已有指纹但凭据库缺少密钥或指纹不匹配，禁止覆盖凭据条目或生成新密钥，以免让现有密文永久不可恢复。

## 导入流程

1. 读取并解析 `.p12` 或 `.pfx` 文件，验证密码、私钥和证书链。
2. 生成身份 ID 和元数据。
3. 进入主密钥初始化及身份写入事务。
4. 序列化身份并使用 AES-256-GCM 加密。
5. 在同一事务中写入身份元数据和密文。
6. 提交成功后向前端返回元数据。

任何步骤失败都不得留下可见但无法使用的身份元数据。敏感中间缓冲区应在可行范围内使用 `zeroize` 清理。

## 加载与旧数据迁移

连接网关时按以下顺序加载身份：

1. 从数据库读取身份密文。
2. 读取系统凭据库中的主密钥并校验数据库指纹。
3. 使用身份 ID 构造 AAD，解密并反序列化身份。
4. 若数据库中不存在该身份的密文，尝试读取旧版 `fun.dbx.gateway/<identity-id>` 密码条目。
5. 旧条目成功解码后，在事务内加密写入数据库。
6. 数据库提交成功后删除旧条目。旧条目删除失败只记录不含敏感数据的警告，不回滚已经成功的迁移。

不存在数据库密文且旧条目也不存在时，返回“网关客户端身份数据不存在”，不得创建新主密钥来掩盖问题。

## 删除流程

删除操作在一个数据库事务中删除身份元数据和密文。事务提交后尽力删除旧版身份凭据条目。主密钥不随最后一个身份删除而自动删除，避免其他实例或尚未完成的迁移失去解密能力。

本次不新增“重置主密钥”功能。此类功能必须显式处理全部现有密文，不能隐式执行。

## 多实例行为

- 已初始化场景仅从系统凭据库读取固定主密钥，并通过 SQLite 读取密文，多实例可并发执行。
- 首次初始化、身份导入、迁移和删除通过 SQLite 写事务串行化。
- 不使用进程内互斥量作为唯一保护，因为它无法协调不同 DBX 进程。
- 写入冲突遵循现有 SQLite busy timeout；超时后返回明确的“网关身份存储正被另一个 DBX 实例修改”错误。

## 错误处理

面向用户的错误至少区分：

- 无法访问操作系统中的 DBX 网关主密钥。
- 当前用户的 DBX 网关主密钥不存在。
- 主密钥与当前 `dbx.db` 不匹配，数据可能来自其他用户或主机。
- 网关身份密文已损坏或认证失败。
- 网关身份数据不存在，需要重新导入客户端证书。
- 数据库正在被另一个 DBX 实例修改。
- 旧版凭据迁移失败。

底层 `keyring::Error` 只用于日志分类。日志不得包含主密钥、私钥、证书原文、PKCS#12 密码或解密后的身份数据。

## 代码边界

- `src-tauri/src/gateway_identity.rs`：身份序列化、加解密、主密钥凭据访问和旧凭据解码。
- `crates/dbx-core/src/storage.rs`：表迁移、主密钥状态、身份元数据与密文的事务性读写。
- `src-tauri/src/commands/gateway.rs`：导入、列出和删除命令编排，不直接处理密码学细节。
- `src-tauri/src/lib.rs`：构造共享同一个数据库存储的身份提供者，不再分别创建无状态 keyring provider。

密码学实现使用项目已经依赖的 AES-256-GCM、系统安全随机数和 SHA-256，不引入自定义加密算法。

## 测试策略

单元测试：

- 大于 Windows Credential Manager 限制的身份数据可完成加密和解密往返。
- 每次加密使用不同 nonce，且均能正确解密。
- 错误主密钥、被修改的密文、被修改的 nonce、错误身份 ID 或格式版本均无法通过认证。
- 主密钥长度、格式版本和指纹校验严格执行。
- 错误映射不会再把大小超限误报为凭据库锁定。

存储测试：

- 元数据和密文同时提交或同时回滚。
- 删除同时移除元数据和密文。
- 已存在密钥状态时禁止替换不匹配的主密钥。
- 两个独立数据库连接竞争首次初始化时最终只接受一个主密钥。

迁移测试：

- 旧凭据成功迁移后数据库可独立加载，旧条目被删除。
- 数据库提交失败时保留旧凭据。
- 旧凭据删除失败不破坏已迁移的数据。

发布验证：

- modern Windows 导入实际网关 `.p12/.pfx` 并完成连接。
- legacy Windows 7/8 构建通过，使用相同数据库格式导入并连接。
- 两个 DBX 实例同时使用同一身份连接网关。
- modern 和 legacy 的便携版、安装版及升级产物按既定发布流程构建。

## 验收标准

- 导入此前触发“操作系统凭据存储不可用或已锁定”的客户端证书能够成功完成。
- Windows Credential Manager 中仅出现固定长度的 DBX 网关主密钥，不再保存完整身份。
- `dbx.db` 中无法检索到 DER 私钥或其 Base64 明文。
- 重启及双实例场景均可使用导入的身份连接网关。
- 旧版已保存身份能够自动迁移；不可迁移时显示可操作的错误信息。
